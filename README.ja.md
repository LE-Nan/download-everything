# download everything

**ウェブページの画像と動画をダウンロードできるプラグイン** —— Instagram・Weibo・X（Twitter）の 3 サイト対応の Chrome 拡張。原図 / 原画質をワンクリックで静かに保存します

[中文](README.md) ｜ [English](README.en.md) ｜ **日本語** ｜ [한국어](README.ko.md)

フィードのカードの横に丸いダウンロードボタンを差し込みます。クリックひとつで元画像・元動画を、あらかじめ指定したフォルダへ**静かに**保存します。「名前を付けて保存」は出ず、画面遷移もなく、閲覧を邪魔しません。
画像・動画は既定で**原図 / 原画質**（Weibo は `large`、X は `name=orig`、Instagram は元画像の最高画質、動画は最高ビットレートの mp4）で保存します。
3 サイトとも**実バイト数の進捗リング**を表示し、読み込み中にもう一度クリックすると**キャンセル**できます。設定ページとポップアップは**中国語 / 英語 / 日本語 / 韓国語**に対応しています。

## 対応サイト

| サイト | 画像 | 動画 | 複数まとめ ZIP | 進捗リング | キャンセル | 個別フォルダ / 画質 |
| --- | --- | --- | --- | --- | --- | --- |
| **Instagram** `instagram.com` | ✅ カルーセル全項目 | ✅ リール・動画投稿 | ✅ | ✅ | ✅ | ✅ |
| **微博（Weibo）** `weibo.com` | ✅ 九宮格すべて | ✅ 原画質・480P〜2K | ✅ | ✅ | ✅ | ✅ |
| **X（Twitter）** `x.com` · `twitter.com` | ✅ グリッド全項目・原図 | ✅ 最高ビットレートの mp4・GIF | ✅ | ✅ | ✅ | ✅ |

3 サイトの実装は**完全に独立**しています。DOM アダプタ、URL 解決チェーン、ボタンのスタイル、ストレージキーがすべて別です。片方のサイトが改版されたり不具合が出たりしても、もう片方には影響しません。

> 拡張の読み込みフォルダ名は今も `ins-download` です（Instagram 専用だった頃の名残）。読み込み時にこのフォルダを選んでください。名前は動作に影響しません。

## 何を解決するか

Instagram の Web 版にはダウンロードボタンがありません。「画像を名前を付けて保存」で得られるのは圧縮されたサムネイルだけで、動画は取れません（プレイヤーは `blob:` URL を流しているので `video.src` をコピーしても使えません）。

微博は事情が異なります。画像は右クリックで保存できますが、既定では `orj360`（幅 360px）の圧縮版です。動画も blob ストリームで、九宮格は 1 枚ずつクリックする必要があります。

**download everything** はこの 2 点を回避します。サイト自身の内部 API に問い合わせて、**その投稿のすべてのメディア項目**と**各画質の実際の CDN URL** を取得し、設定した解像度でダウンロードします。

## 機能一覧

### 共通

| 機能 | 内容 |
| --- | --- |
| 🖼 **画像ダウンロード** | 単体画像、カルーセル、九宮格に対応。設定した解像度に最も近い画質を選択 |
| 🎬 **動画ダウンロード** | 実際の mp4 URL（blob ではない）を取得。リール、動画投稿、微博動画に対応 |
| 🎠 **カルーセル / 九宮格の全件** | 10 枚の投稿から 10 項目すべて取得。遅延読み込みの影響を受けません（DOM には通常 2〜3 枚しかありません） |
| 📦 **ZIP まとめ** | 複数枚を 1 つの ZIP に。「名前を付けて保存」を 10 回押す必要はありません |
| 📁 **保存先の指定** | 一度フォルダを選べば以後は無確認で書き込み。画像と動画で別フォルダも可 |
| ⚙️ **解像度** | 3 サイト共通の**7 段**：**原図（既定）** / 240P / 480P / 720P / 1080P / 2K / 4K |
| 🎚 **動画画質** | 3 サイト共通の 5 段階：**原画質（既定）** / 標準 480P / 高画質 720P / 超高画質 1080P / ウルトラ HD 2K |
| 🎛 **サイト別スイッチ** | ポップアップで Instagram と微博を個別に ON/OFF |
| 🧩 **依存ゼロ** | 素の JavaScript。ビルドも npm も不要で、clone してすぐ使えます |

### Instagram の実装済み機能

- **ボタン挿入**：各フィードの `article` の**右外側**に丸いボタンを 1 つ。`position: fixed` でカードに追従し、スクロール / ズーム / フィード再配置のたびに `requestAnimationFrame` でまとめて再配置。遅れず、重なりません
- **URL 解決は 5 段階フォールバック**：内部メディア API → `?__a=1` → embed ページ → 投稿ページの HTML → DOM フォールバック（「動作の仕組み」参照）
- **カルーセル全件**：API が全項目を一度に返すため、遅延読み込みの影響なし
- **画質**：画像は `image_versions2.candidates` / `srcset` から、原図は最大のもの、指定した段は「その段以上の最小」を選択（240P〜4K）。動画も `video_versions[].width` に同じ規則を適用（原画質 / 480P / 720P / 1080P / 2K）
- **複数項目メニュー**：`現在の 1 枚をダウンロード` / `全 N 項目をまとめて ZIP`
- **バイト先行**：オフスクリーン文書が実際のバイト列を取得してから受け渡すため、拡張子は実際のファイルヘッダで決まります。CDN のエラーページで拡張子を書き換えられることはもうありません
- **進捗リング**：ボタン外縁が実バイト数で時計回りに塗られます（解決中は時間ベース、取得中はバイト比率）。保存ダイアログと連動
- **キャンセル**：読み込み中にもう一度クリックで中止。取得リクエストを切断し、開いてしまった保存ダイアログも閉じ、静かに終了します
- **ファイル名**：`ins_image_20261119T201500.jpg` / `ins_video_….mp4`。ZIP 内は連番

### 微博の実装済み機能

- **カード検出**：壊れやすいクラス名に依存しません。最も近い祖先が `article.woo-panel-main` / `div.card-wrap` / `[action-type=feed_list_item]` / `[mid]` / `[data-mid]` に一致するかで判定。新しいホームと検索ページの両方で動作します
- **投稿 ID の 2 経路**：コンテナに `mid` / `data-mid` があればそれを使用。なければカード内リンク（`/{uid}/{mblogid}`、`/detail/xxx`、`/status/xxx`）から `mblogid` を抽出
- **メディア解決**：`/ajax/statuses/show` → 動画コンポーネント API → DOM フォールバック。九宮格、画像＋動画の混在（表示順を維持）、転送投稿に対応
- **画像画質**：`sinaimg.cn` のパス先頭を差し替え（`orj360` / `mw690` / `orj1080` / `large` 原画）。存在しない画質は自動的に原画へフォールバック
- **動画画質**：原画質 / 標準 480P / 高画質 720P / 超高画質 1080P / ウルトラ HD 2K。コンポーネント API の解像度リストを `quality_label`（無い場合は `mp4_720p` / `label=mp4_hd` などの手掛かり）で段に分けてから設定順に並べます
- **バイト先行**：オフスクリーン文書が実バイトを取得してから受け渡すため、「ダウンロードしたら `.htm` だった」問題を根本的に解消
- **Referer の自動付与**：`declarativeNetRequest` のセッションルールで、画像ホストと動画 CDN にのみ `Referer: https://weibo.com/` を付与（`weibo.com` 自体には付けません）。403 を回避
- **ボタン位置**：カードのアイコンと縦中央で揃えます。アイコンが画面外に出たとき、またはカードが固定ヘッダーの下に潜ったときはボタンも隠れ、ナビゲーションバーの上に浮くことはありません。横方向はビューポート内に収まります
- **進捗リング**：実バイト数で時計回り。保存ダイアログと連動
- **キャンセル**：読み込み中にもう一度クリック。取得リクエストを切断し、開いている保存ダイアログも閉じます
- **複数項目メニュー**：`1 項目目だけダウンロード` / `全 N 項目をまとめて ZIP`
- **ファイル名**：`weibo_image_20261119T201500.jpg` / `weibo_video_….mp4` / `weibo_images_….zip`

### 診断機能

両方のコンテンツスクリプトにコンソールコマンド（`__insDl.*` / `__wbDl.*`）と `[download-everything]` プレフィックスのログがあります。サイト改版時に「カードが認識されていない」のか「URL 解決に失敗している」のかを、ソースを読まずに切り分けられます。詳細は[デバッグ](#デバッグ)を参照。

## インストール

Chrome ウェブストアには公開していません。開発者モードでローカルから読み込みます。

1. リポジトリを clone
   ```bash
   git clone https://github.com/LE-Nan/download-everything.git
   ```
2. `chrome://extensions`（Edge は `edge://extensions`）を開く
3. 右上の **デベロッパーモード** を ON
4. **パッケージ化されていない拡張機能を読み込む** をクリックし、リポジトリ内の **`ins-download`** フォルダを選択
5. [instagram.com](https://www.instagram.com) または [weibo.com](https://weibo.com) を開き、フィードを表示すると各投稿の横にボタンが現れます

> Chrome 109 以上が必要です（`chrome.offscreen` と File System Access API を使用）。古いブラウザでは「劣化時の動作」を参照してください。
>
> 拡張は `declarativeNetRequestWithHostAccess` 権限を使用します（微博の CDN に Referer を付けるため）。更新後、Chrome が新しい権限の承認を求めるので、再読み込みして承認してください。

## 使い方

### Instagram

フィードのカードにマウスを乗せると、カードの**右外側**に丸いボタンが現れます。クリックしてください。

- 画像 1 枚 / 動画 1 本の投稿 → すぐにダウンロード開始。成功で緑、失敗で赤
- カルーセル投稿 → 2 つの選択肢：
  - **現在の 1 枚をダウンロード** — いま表示されている 1 枚だけ
  - **全 N 項目をまとめて ZIP** — すべてを 1 つの ZIP に
- クリック後は**進捗リング**が進みます。読み込み中にもう一度クリックすると**キャンセル**（アイコンが塗りつぶし四角になり、ホバーで赤くなります）

### 微博

操作は同じです。各カードの**右側**に同じ丸いボタンが出ます（ホバーで微博オレンジ）。

- 画像 1 枚 / 動画 1 本 → 直接ダウンロード
- 九宮格 / 複数画像 → **1 項目目だけ** または **全 N 項目をまとめて ZIP**

ボタンは**カードのアイコンと縦中央で揃い**、「この投稿のダウンロードボタン」であることを示します。アイコンが画面外に出るとボタンも隠れ、**カードが固定ナビゲーションの下に潜ったときも隠れます**（ナビの上に浮きません）。横方向はビューポート内に収まり、右サイドバーにはみ出しません。ボタンが出ない投稿があれば、コンソールで `__wbDl.debug()` を実行してください（[デバッグ](#デバッグ)参照）。

### 進捗リング

動画はクリックから保存ダイアログが出るまで通常 5〜15 秒かかります。以前は半透明になるだけで、動いているのか分かりませんでした。現在は**ボタンの外縁がそのまま進捗バー**です（両サイト共通）。

```
クリック ──▶ メディア解決（0→12%、時間ベースで緩やかに上昇）
        ──▶ バイト取得（取得済みバイト / Content-Length で時計回りに緑で塗る）
        ──▶ 100% まで塗る  ← ここで保存ダイアログが開く
        ──▶ 「保存」をクリック  ← ボタンが元に戻り、塗りが消える
```

- 取得済みの部分は**緑**、未取得は**空のまま**、時計回りに進行
- `Content-Length` がない場合は時間ベースで上昇し、最大 92% で止まります（完了したふりはしません）
- 保存ダイアログが開いている間はリングは満杯のまま。ダウンロードが `complete` になって初めて元に戻ります
- キャンセルでもボタンは元に戻り、エラーも 2 回目のダイアログも出ません

### キャンセル

**読み込み中にもう一度ボタンをクリックするとキャンセル**です。このときボタンは塗りつぶし四角になり、ホバーで赤く、ツールチップは「ダウンロード中、クリックでキャンセル」に変わります。「もう一度押す」という操作を腑に落とすための変更です。

キャンセルは UI だけを畳むのではなく、3 層すべてが停止します。

| 段階 | キャンセル時の動作 |
| --- | --- |
| メディア解決（API 待ち） | ローカルで記録し、API が返っても何も送らない（メニューもダウンロード要求も出さない） |
| バイト取得 / ZIP 作成（5〜15 秒） | `AbortController` で `fetch` を切断し、読み取りループも抜ける。数十 MB を無駄に落とさない |
| 保存ダイアログが開いている | `chrome.downloads.cancel()` でそのダウンロードを閉じる |

キャンセルは静かです。赤く点滅せず、再試行せず、2 回目のダイアログも出さず、下部に中立のトースト「キャンセルしました」を出すだけです。また**そのダウンロードを開始したボタン**だけがキャンセルできます。別のカードのボタンを押すと「別の項目をダウンロード中です」と出るだけで、他人のタスクを止めたと誤解させません。

### 設定ページ：保存先 / 表示設定

ツールバーのアイコン → **設定を開く**。設定ページは Chrome の設定と同じ左右 2 カラム（左がナビ、右が内容）です。

| 分欄 | 内容 |
| --- | --- |
| **保存先** | 2 サイトの保存フォルダと画質 |
| **表示設定** | 表示言語（中国語 / 英語 / 日本語 / 韓国語） |

「保存先」はサイトごとに 2 つのカードに分かれます（**Instagram ダウンロード設定** / **微博ダウンロード設定**）。サイト名の見出しはカード枠の外にあり、括弧内のサイト名はクリックで各サイトへ移動できます。各カードの内部は画像グループと動画グループに分かれ、4 グループは互いに独立です。現在の分欄は URL のハッシュに残り、`options.html#display` で表示設定を直接開けます。

| 設定項目 | 値 | 既定 |
| --- | --- | --- |
| Instagram 画像フォルダ / 解像度 | 任意フォルダ、原図（既定）/ 240P〜4K | `Downloads\ins-download\images` |
| Instagram 動画フォルダ / 画質 | 任意フォルダ、原画質（既定）/ 480P / 720P / 1080P / 2K | `Downloads\ins-download\videos` |
| 微博 画像フォルダ | 任意 / 既定 | `Downloads\weibo-download\images` |
| 微博 画像解像度 | 原図（既定）/ 240P / 480P / 720P / 1080P / 2K / 4K（Instagram と共通） | サイズ別パスを書き換え、`orj360` / `orj480` / `mw690` / `mw1024` / `orj1080` / `mw2000` / `large`（原図）に対応 |
| 微博 動画フォルダ | 任意 / 既定 | `Downloads\weibo-download\videos` |
| 微博 動画画質 | 原画質（既定）/ 480P / 720P / 1080P / 2K | API の画質ラベルで段を判定し、判定できない URL は最後のフォールバック |

**任意フォルダについて**：「フォルダを選択」でシステムのダイアログから任意のディレクトリを選べます。以後はすべて無確認で書き込まれます。ディレクトリハンドルは IndexedDB に保存します。

> ⚠️ **ブラウザを再起動すると権限が失効します**（File System Access API の仕様上の制限）。設定ページに「再認証が必要」と表示されるので、**再認証** を押して同じフォルダをもう一度選んでください。ダウンロード済みのファイルには影響しません。

### 表示言語

**表示設定 → 表示言語** で中国語 / 英語 / 日本語 / 韓国語を切り替えられます。設定ページ、ツールバーのポップアップ、ページ内ボタンのツールチップ・メニュー・エラー通知まで四言語で表示されます。

- 切り替えは**即時反映**：設定ページとポップアップはその場で、ページに注入済みのボタンも再読み込みなしでツールチップが変わります
- 未選択の場合はブラウザの言語から一度だけ推定します（`zh*` → 中国語、`ja` → 日本語、`ko` → 韓国語、それ以外は英語）。表示のみで、保存はしません
- 選択は `chrome.storage.sync` の `uiLang` に保存され、更新や同期後も保持されます
- 辞書は `i18n.js`。四言語のキー集合は `test-i18n.js` が見張っているので、訳が欠けるとテストが落ちます

### 劣化時の動作

任意フォルダを設定していない場合、拡張は `chrome.downloads` を使い、ブラウザの既定ダウンロードフォルダ内のサブフォルダに保存します。ブラウザの設定によってはこの経路でも保存ダイアログが 1 回出ることがあります。これはブラウザの挙動で、拡張側では回避できません。

## 動作の仕組み

### 全体アーキテクチャ

```
Instagram のページ              微博のページ
content.js（分離ワールド）      weibo.js（分離ワールド）
   │  chrome.runtime.sendMessage   │
   ▼                               ▼
background service worker  ←──────┘   （msg.site で振り分け）
   │  ensureOffscreen()
   ▼
オフスクリーン文書：実バイトを取得（中断可能）→ blob / dataUrl / 直接書き込み
   │
   ▼
chrome.downloads.download()  →  指定フォルダに保存
```

- コンテンツスクリプトはネットワークの本体に触れません。ページを読み、UI を描くだけです
- 重い処理はオフスクリーン文書が担当します。DOM があり、ホスト権限を持つため CORS の制約を受けません
- service worker は長期状態を持ちません。すべて `progressId` をキーにしたマップで、30 秒後に掃除されます

### メディア URL 解決：5 段階フォールバック（Instagram）

1. `/api/v1/media/{media_id}/info/`（`X-IG-App-ID` 付き）— 最も安定。カルーセル全項目と全画質を返します
2. `/p/{shortcode}/?__a=1&__d=dis`
3. `/p/{shortcode}/embed/captioned/` の HTML を正規表現で抽出
4. `/p/{shortcode}/` の HTML を正規表現で抽出
5. DOM フォールバック：`srcset` / `video.src` を可視性と動画レイヤーとの重なりで絞り込み

### 微博のメディア解決

`/ajax/statuses/show?id=…` → 動画コンポーネント API（`Component_Play_Playinfo`）→ DOM フォールバック。画像 URL は画質ごとに書き換え、存在しない画質は原画へフォールバックします。

### なぜ URL をダウンローダに渡さず、バイトを先に取るのか

ダウンローダ自身に URL を取得させると、リクエストの出自は `chrome-extension://` になり、ページの Referer も付きません。微博の CDN はその場合 **200 の HTML エラーページ**を返し、Chrome はそれを `.htm` として保存します。これが「ダウンロードしたファイルが `.htm` になる」不具合の根本原因でした。先にバイトを取得し、ファイル名と MIME タイプを拡張側が決めれば、この可能性自体が消えます。オフスクリーン文書が作った `blob:` URL を受け付けない Chrome では、自動的に `dataUrl` で再試行します。

Instagram では同じ仕組みが進捗リングに必要なバイト列ももたらします。バイト取得に失敗した場合は**従来の直接ダウンロードへ自動フォールバック**するので、CDN の一時的な拒否で「本来落とせるものが落とせない」状態にはなりません。

### 進捗リングとキャンセルのデータ経路

```
content.js / weibo.js が progressId を生成
   │
   ├─▶ background が sender.tab.id を progressTabs に記録
   │
   ├─▶ offscreen save-media：getReader() でストリーム読み、120ms ごとに {loaded,total} を報告
   │        └─▶ background ─▶ tabs.sendMessage(type:"wb-dl-progress") ─▶ リング描画
   │
   ├─▶ chrome.downloads を呼ぶ直前に phase:"save"（=100%）を送信 → 保存ダイアログが開く
   │
   └─▶ もう一度クリック ─▶ action:"cancel" ─▶ offscreen abort（AbortController）
                                            └▶ chrome.downloads.cancel(downloadId)
```

`progressId` が全工程を通します。キャンセルがダウンロード要求より**先に**届いても記録され（二度押しのケース）、タスク開始時に確認して既にキャンセル済みなら即座に返します。3 段階のキャンセル結果はすべて `canceled` に正規化されるため、上位は「成功 / キャンセル / 失敗」の 3 状態だけを扱います。

> 両サイトは同じ進捗チャネルを共有します（メッセージ種別は歴史的な `wb-dl-progress` のまま）。各コンテンツスクリプトは自分のボタンのリングだけを描きます。`progressId` の接頭辞は異なり（`ig…` / `wb…`）、旧 `wb-cancel` と新 `cancel` の両方を受け付けます。

### ボタンを `body` に置く理由

初期実装ではボタンを `article` の中に置き、メディアの右上に配置していました。2 つの問題がありました。

1. **動画の透明な操作レイヤーがクリックを奪う** — Instagram は動画の上に全画面の `<div>` を重ねて再生制御を行うため、`z-index` を上げてもそのスタッキングコンテキスト内では効きません
2. 標準の `···` メニューボタンと重なる

最終的な方式は、ボタンを `document.body` の子にし、`position: fixed` + `z-index: 2147483647`、`getBoundingClientRect()` でカードに追従、`scroll` / `resize` / 変更監視のたびに `requestAnimationFrame` でまとめて再配置するというものです。ボタンはカードの**外側**に置くため、カード内のあらゆる操作要素と衝突しません。

### 2 つのサイトが互いに影響しない仕組み

| 分離軸 | Instagram | 微博 |
| --- | --- | --- |
| コンテンツスクリプト | `content.js` | `weibo.js` |
| スタイル接頭辞 | `.ins-dl-*` | `.wb-dl-*` |
| スイッチのキー | `enabled` | `weiboEnabled` |
| ディレクトリのキー | `imageDir` / `videoDir` / … | `weiboImageDir` / `weiboVideoDir` / … |
| ファイル名の接頭辞 | `ins_image_` / `ins_video_` | `weibo_image_` / `weibo_video_` |
| 既定フォルダ | `ins-download/` | `weibo-download/` |

`background.js` で両者が接するのは、各ハンドラ先頭の `if (msg.site === "weibo")` 1 行だけです。

## 既知の制限

うまくできない点を正直に挙げます。

1. **Instagram はフィードの `article` のみ**。投稿詳細 `/p/xxx/`、単独のリールページ、ストーリーズ、DM、プロフィールの九宮格には**まだボタンが出ません**。
2. **Instagram はバイト取得に失敗すると直接ダウンロードへ戻ります**（進捗リングなし、キャンセルも効きません）。CDN の一時的な拒否で「本来落とせるもの」を壊さないための意図的な設計です。ログに `ins 取字节失败，退回直拉` が出ます。
3. **動画を含むカルーセルの ZIP は画像フォルダに入ります**（Instagram のみ）。`handleZip` が `imageDir` しか読まないためです。微博側は内容種別で振り分け済みです。
4. **巨大な ZIP はメモリ上のリスク**があります。既定フォルダ方式では ZIP を dataUrl 文字列としてコンテキスト間で渡すため、およそ 100MB を超えると失敗しやすくなります。
5. **動画画質の選択が不正確**（Instagram のみ）。`video_versions[].width` が 0 のことが多く、実際には配列の末尾要素になります。
6. **Instagram のアニメーション投稿 / ストーリーズのメディア**は未対応です。
7. **微博のセレクタは公開されている類似スクリプト**（owendswang / firo1603 の「微博の画像と動画をダウンロード」）を参考にし、API フィールドは `pic_infos` / `playback_list` / `Component_Play_Playinfo` の実際の形に合わせていますが、ログイン状態で全ページを網羅的に検証したわけではありません。ボタンが出ない場合はまず `__wbDl.debug()` を実行してください。多くの場合 `SEL` の修正だけで済みます。
8. **微博はフィードと一覧ページのみ**。画像ビューアのオーバーレイ、単独の動画ページ、ヘッドライン記事、DM は未対応です。
9. **微博の転送投稿**では転送元のメディアを取得します（一部のレイアウトでは転送者の画像も混ざります）。
10. **保存ダイアログが開く瞬間のキャンセル**は Chrome の `downloads.cancel` の挙動に依存し、一部のバージョンでは「キャンセル済み」の項目がダウンロード一覧に残ることがあります（ファイルは書き込まれません）。
11. サイト改版で解決チェーンが壊れることがあります。Instagram は `content.js`、微博は `weibo.js` を修正してください。

- **Instagram にも進捗リング**：解決中は 0→12% を時間ベースで、取得中は `取得済みバイト / Content-Length` で時計回りに塗り、バイト取得完了で 100%（この瞬間に保存ダイアログが開く）、ダイアログが閉じてから元に戻ります。データは従来どおりオフスクリーンのストリーム報告を `progressId` 経由で受け取ります
- **Instagram もキャンセル可能**：読み込み中にもう一度クリックで 3 層すべて停止（ローカルのリング解除、`AbortController` による切断、ダイアログが開いていれば `chrome.downloads.cancel()`）。ボタンは塗りつぶし四角になり、ホバーで赤、ツールチップは「ダウンロード中、クリックでキャンセル」
- **Instagram はバイト先行に変更**：URL を直接 `chrome.downloads` に渡さず、オフスクリーン文書が実バイトを取得してから受け渡します（拡張子は実ファイルヘッダで決定）。取得に失敗した場合は**従来の直接ダウンロードへ自動フォールバック**し、CDN の一時的な拒否で「本来落とせるもの」が壊れないようにしました
- ZIP まとめも進捗とキャンセルに対応（項目数で進行、キャンセル時はアーカイブを破棄）
- `__insDl.*` のコンソール診断を追加（`debug` / `media` / `ring` / `cancel` / `clearCache`）。`__wbDl.*` と揃えました
- 回帰テスト 202 → **242 件**（`test/test-content.js` 30 件を追加、`test-background.js` 81 → 91 件）
- README に English / 日本語 / 한국어 を追加し、上部に言語切り替えを設置

### v2.0.1（2026-11-20）

UI と命名の整理のみ。ダウンロード処理は変更なし：

- 表示名 `ins download` → **download-everything**（リポジトリ名と一致）。ポップアップのタイトル、ボタンのツールチップ、`[download-everything]` ログ接頭辞も統一

- 設定ページ：両サイトの見出しを**カード枠の外**に出して同じ文字サイズに統一。括弧内のサイト名はクリック可能。Instagram の画像・動画設定は 1 枚のカードに統合
- 読み込みフォルダ、既定のサブフォルダ（`Downloads\ins-download\*`、`Downloads\weibo-download\*`）、すべてのストレージキーは不変。既存の設定とダウンロード済みファイルに影響なし

### v1.3.1（2026-11-19）

読み込み中の「逃げ道」を追加。Instagram 側は変更なし：

- **読み込み中にもう一度クリックでキャンセル** — 以前は読み込み中にボタンが無反応で、動画の 5〜15 秒から抜ける手段がありませんでした
- **キャンセルは 3 層で実施**：解決処理を打ち切り、オフスクリーンの `fetch` と読み取りループを `AbortController` で切断し、保存ダイアログが開いていれば `chrome.downloads.cancel()`
- **読み込み中はボタンが停止アイコンに**：矢印から塗りつぶし四角へ、ホバーで赤、ツールチップは「ダウンロード中、クリックでキャンセル」
- **キャンセルは静か**：赤く点滅せず、再試行せず、2 回目のダイアログも出さず、中立のトーストのみ
- **二度押し対策**：1 つの `progressId` が 3 段階を通し、ダウンロード要求より先に届いたキャンセルも記録してタスク開始時に確認
- キャンセルできるのは、そのダウンロードを開始したボタンだけ
- コンソールから `__wbDl.cancel()` で手動キャンセル可能
