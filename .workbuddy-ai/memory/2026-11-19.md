## v1.2.0 修微博两个实锤 bug

- **下载成 .htm 的根因（两条）**：① 图片换档把 /orj360/ 改成 /orj1080/，微博多数图没有 1080 档 → 404 HTML；② s.weibo.com 上没有 /ajax/statuses/show（返回 HTML 登录页），旧代码没校验就当接口用了。Chrome 识别内容为 HTML 即把 .jpg 改成 .htm。
- **首页无按钮的根因**：新版首页卡片是 `<article class="woo-panel-main">`，**没有 mid 属性**；旧代码只认 [mid]，故只有 s.weibo.com 的 div.card-wrap 命中。
- 证据来源：GitHub 上仍在维护的 owendswang / firo1603「下载微博图片和视频」userscript（用 api.github.com contents 拉源码读的，沙箱能通 api.github.com，但 weibo.com/m.weibo.cn 全部要登录，访客 Cookie 也进不去）
- 新取址链路：GET /ajax/statuses/show?id={mblogid|mid}（pic_infos+pic_ids / mix_media_info / page_info.media_info）→ POST /tv/api/component?page=/tv/show/{fid}（Component_Play_Playinfo.urls，全部分辨率，url 以 // 开头需补 https:）→ DOM 兜底
- 卡片选择器（最近祖先优先）：article.woo-panel-main / div.card-wrap / [action-type=feed_list_item] / [mid] / [data-mid]；帖子 id 兜底从链接取 /{uid}/{mblogid}
- 下载前先探测：offscreen 用 4KB Range GET 每个候选，校验 content-type 非 html/json + 文件头（jpg/png/gif/webp/ftyp/mov/webm），定真实扩展名后再交 chrome.downloads；全失败返回 media-blocked，不落盘

## v1.2.1 修「单图/视频仍存成 .htm」并改按钮定位

- **真根因（关键认知）**：`chrome.downloads` 自己去拉微博 CDN 地址会失败 —— 下载请求由浏览器发起，带 chrome-extension:// 来源、**没有页面 Referer**，图床/视频 CDN 回 **200 的 HTML 错误页**，Chrome 见 text/html 就改名 .htm。**多图 zip 一直正常正是因为它传的是本地 dataUrl，不是网络地址**。v1.2.0 的 Range 探测能过、最终文件却是 .htm，就是因为「探测请求」和「下载请求」不是同一个请求。
- 修法：offscreen 取回**真实字节**再交付 —— 图片 ≤6MB 走 dataUrl（与 zip 同一条已验证路径），视频走 blob URL（离屏文档 createObjectURL，background 调 chrome.downloads），blob 被拒时回退 dataUrl。MIME 与后缀都由本地 blob 决定，服务器无法再改。
- 大视频用 `resp.blob()` 而非 `arrayBuffer()`（Chrome 会把大 Blob 落盘），加 `got.blob.slice(0, size, mime)` 只换 type 不复制。
- 候选地址补全：q → large → mw2000 → orj1080 → mw690 → orj360 → **原样地址**（保底）。
- 按钮定位：`avatarOf(root)` 找卡片左上角 24~88px 方形图（优先 src 含 /crop. 或 /avatar/），按钮纵向与头像**居中**对齐；`ar.bottom > 8` 才显示 → 头像滑出视口顶部按钮一起隐藏（用户明确要求）。头像找不到时 2s 重试一次，避免每帧 querySelectorAll。
- 卸载 probe-media 协议（delete），offscreen 现在只有 save-media / blob-dataurl / release-blob / weibo-api / zip / handleSingle。zip 与 handleSingle 走原逻辑，ins 完全不受影响。
- 测试 120 断言：weibo 34 / offscreen 40 / background 46，全绿；content.js、content.css 在 diff 中依旧零出现。
- 仍未实测：真实登录态（沙箱进不去 weibo）。用户需 `chrome://extensions` 刷新 + 硬刷新页面后验证单图/视频。
- 追加（同轮）：`watchDownload(downloadId)` —— blob URL 被 Chrome **异步**拒（downloadId 已返回、随后 state=interrupted）时回调不报错，只靠回调会误判成功。现在短暂盯状态（先 downloads.search 查一次避免竞态，再 onChanged），interrupted 即回退 dataUrl。测试 +3（49 项）。
