# download everything

**인스타그램 · 웨이보 웹 버전 이미지 / 동영상 원클릭 다운로드 Chrome 확장**

[中文](README.md) ｜ [English](README.en.md) ｜ [日本語](README.ja.md) ｜ **한국어**

피드 카드 옆에 둥근 다운로드 버튼을 넣습니다. 한 번 누르면 원본 이미지·원본 동영상이 미리 지정한 폴더로 **조용히** 저장됩니다. "다른 이름으로 저장" 창도, 화면 이동도, 브라우징 방해도 없습니다.
두 사이트 모두 **실제 바이트 기준 진행 링**을 표시하며, 로딩 중에 다시 누르면 **취소**됩니다.

## 지원 사이트

| 사이트 | 이미지 | 동영상 | 여러 항목 ZIP | 진행 링 | 취소 | 사이트별 폴더 / 화질 |
| --- | --- | --- | --- | --- | --- | --- |
| **Instagram** `instagram.com` | ✅ 캐러셀 전체 항목 | ✅ 릴스 · 동영상 게시물 | ✅ | ✅ | ✅ | ✅ |
| **웨이보** `weibo.com` | ✅ 9칸 그리드 전체 | ✅ HD / SD | ✅ | ✅ | ✅ | ✅ |

두 사이트의 구현은 **완전히 독립적**입니다. DOM 어댑터, URL 해석 체인, 버튼 스타일, 저장 키가 모두 분리되어 있어 한쪽 사이트가 개편되거나 오류가 나도 다른 쪽에는 영향이 없습니다.

> 확장 로드 폴더 이름은 여전히 `ins-download` 입니다(인스타그램 전용이던 시절의 이름). 로드할 때 이 폴더를 선택하면 되고, 이름은 동작에 영향을 주지 않습니다.

## 무엇을 해결하나

인스타그램 웹에는 다운로드 버튼이 없습니다. "이미지를 다른 이름으로 저장"으로는 압축된 썸네일만 얻을 수 있고, 동영상은 아예 얻을 수 없습니다(플레이어가 `blob:` URL을 스트리밍하므로 `video.src`를 복사해도 쓸 수 없습니다).

웨이보는 상황이 다릅니다. 이미지는 우클릭으로 저장되지만 기본값이 `orj360`(너비 360px) 압축본이고, 동영상 역시 blob 스트림이며, 9칸 그리드는 한 장씩 눌러야 합니다.

**download everything** 은 이 두 가지를 우회합니다. 사이트 자체의 내부 API에 요청해 **해당 게시물의 모든 미디어 항목**과 **각 화질의 실제 CDN URL** 을 받아, 설정한 해상도로 저장합니다.

## 기능 개요

### 공통

| 기능 | 설명 |
| --- | --- |
| 🖼 **이미지 다운로드** | 단일 이미지, 캐러셀, 9칸 그리드 지원. 설정한 해상도에 가장 가까운 화질 선택 |
| 🎬 **동영상 다운로드** | 실제 mp4 URL(blob 아님)을 획득. 릴스, 동영상 게시물, 웨이보 동영상 지원 |
| 🎠 **캐러셀 / 그리드 전체** | 이미지 10장 게시물에서 10개 항목 전부 획득. 지연 로딩 영향 없음(DOM에는 보통 2~3장만 렌더링됨) |
| 📦 **ZIP 묶음** | 여러 장을 ZIP 하나로. "다른 이름으로 저장"을 10번 누를 필요 없음 |
| 📁 **폴더 지정** | 한 번 폴더를 고르면 이후 무확인으로 기록. 이미지와 동영상을 다른 폴더로 분리 가능 |
| ⚙️ **화질 선택** | Instagram 240P~4K, 웨이보 360P / 690P / 1080P / 원본 |
| 🎛 **사이트별 스위치** | 팝업에서 Instagram과 웨이보를 각각 켜고 끔 |
| 🧩 **의존성 없음** | 순수 JavaScript. 빌드도 npm도 없이 clone 후 바로 사용 |

### Instagram 구현 내용

- **버튼 주입**: 각 피드 `article`의 **오른쪽 바깥**에 둥근 버튼 하나. `position: fixed`로 카드를 따라가며, 스크롤 / 확대 / 피드 재배치 시 `requestAnimationFrame`으로 일괄 재배치. 늦지도 겹치지도 않습니다
- **URL 해석 5단계 폴백**: 내부 미디어 API → `?__a=1` → embed 페이지 → 게시물 페이지 HTML → DOM 폴백("동작 원리" 참조)
- **캐러셀 전체**: API가 모든 항목을 한 번에 반환하므로 지연 로딩과 무관
- **화질**: 이미지는 `image_versions2.candidates` / `srcset`에서 설정 너비에 가장 가까운 것을 선택(240P~4K), 동영상은 `video_versions`에서 선택
- **여러 항목 메뉴**: `현재 항목만 다운로드` / `전체 N개 항목을 ZIP으로`
- **바이트 우선**: 오프스크린 문서가 실제 바이트를 받아 전달하므로 확장자가 실제 파일 헤더로 결정됩니다. CDN의 오류 페이지가 확장자를 바꿀 수 없습니다
- **진행 링**: 버튼 바깥 고리가 실제 바이트만큼 시계 방향으로 채워집니다(해석 단계는 시간 기반, 다운로드 단계는 바이트 비율). 저장 창과 연동
- **취소**: 로딩 중 다시 클릭하면 중단. 요청을 끊고 이미 열린 저장 창도 닫으며 조용히 종료합니다
- **파일명**: `ins_image_20261119T201500.jpg` / `ins_video_….mp4`. ZIP 내부는 순번

### 웨이보 구현 내용

- **카드 탐지**: 깨지기 쉬운 클래스명에 의존하지 않습니다. 가장 가까운 조상이 `article.woo-panel-main` / `div.card-wrap` / `[action-type=feed_list_item]` / `[mid]` / `[data-mid]` 인지로 판단. 새 홈과 검색 페이지 모두 동작
- **게시물 id 두 경로**: 컨테이너에 `mid` / `data-mid` 가 있으면 사용, 없으면 카드 내 링크(`/{uid}/{mblogid}`, `/detail/xxx`, `/status/xxx`)에서 `mblogid` 추출
- **미디어 해석**: `/ajax/statuses/show` → 동영상 컴포넌트 API → DOM 폴백. 9칸 그리드, 이미지+동영상 혼합(보이는 순서 유지), 리포스트 지원
- **이미지 화질**: `sinaimg.cn` 경로 첫 세그먼트 교체(`orj360` / `mw690` / `orj1080` / `large` 원본). 없는 화질은 자동으로 원본 폴백
- **동영상 화질**: HD / SD, 컴포넌트 API의 해상도 목록에서 직접 획득
- **바이트 우선**: 오프스크린 문서가 실제 바이트를 받아 전달하므로 "받은 파일이 `.htm`" 문제를 근본적으로 해결
- **Referer 자동 보강**: `declarativeNetRequest` 세션 규칙으로 이미지 호스트와 동영상 CDN에만 `Referer: https://weibo.com/` 를 추가(`weibo.com` 자체는 건드리지 않음). 403 회피
- **버튼 위치**: 카드 아바타와 세로 중앙 정렬. 아바타가 화면을 벗어나거나 카드가 고정 헤더 아래로 들어가면 버튼도 숨김(내비게이션 바 위에 뜨지 않음). 가로로는 뷰포트 안으로 자동 축소
- **진행 링**: 실제 바이트 기준, 시계 방향, 저장 창과 연동
- **취소**: 로딩 중 다시 클릭. 요청을 끊고 열린 저장 창도 닫음
- **여러 항목 메뉴**: `첫 번째 항목만` / `전체 N개 항목을 ZIP으로`
- **파일명**: `weibo_image_20261119T201500.jpg` / `weibo_video_….mp4` / `weibo_images_….zip`

### 진단 기능

두 콘텐츠 스크립트 모두 콘솔 명령(`__insDl.*` / `__wbDl.*`)과 `[download-everything]` 접두사 로그를 제공합니다. 사이트가 개편되어도 소스를 읽지 않고 "카드를 못 찾았는지"와 "주소 해석이 실패했는지"를 구분할 수 있습니다. 자세한 내용은 [디버깅](#디버깅) 참조.

## 설치

Chrome 웹스토어에는 올라가 있지 않습니다. 개발자 모드로 로컬에서 로드합니다.

1. 저장소 clone
   ```bash
   git clone https://github.com/LE-Nan/download-everything.git
   ```
2. `chrome://extensions` 열기(Edge는 `edge://extensions`)
3. 오른쪽 위 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드** 클릭 후 저장소의 **`ins-download`** 폴더 선택
5. [instagram.com](https://www.instagram.com) 또는 [weibo.com](https://weibo.com) 을 열고 피드로 이동하면 각 항목 옆에 버튼이 나타납니다

> Chrome 109 이상 필요(`chrome.offscreen` 과 File System Access API 사용). 구버전 브라우저는 "저하 동작"을 참고하세요.
>
> 확장은 `declarativeNetRequestWithHostAccess` 권한을 사용합니다(웨이보 CDN에 Referer를 붙이기 위함). 업데이트 후 Chrome이 새 권한 승인을 요청하면 다시 로드하고 수락하세요.

## 사용법

### Instagram

피드 카드에 마우스를 올리면 카드 **오른쪽 바깥**에 둥근 버튼이 나타납니다. 클릭하세요.

- 이미지 1장 / 동영상 1개 → 즉시 다운로드 시작. 성공하면 초록, 실패하면 빨강
- 캐러셀 게시물 → 두 가지 선택지:
  - **현재 항목만 다운로드** — 지금 보이는 한 장만
  - **전체 N개 항목을 ZIP으로** — 전부 하나의 ZIP으로
- 클릭 후 **진행 링**이 차오릅니다. 로딩 중 다시 클릭하면 **취소**(아이콘이 채워진 사각형이 되고 호버 시 빨갛게 변함)

### 웨이보

조작은 동일합니다. 각 카드 **오른쪽**에 같은 둥근 버튼이 나타납니다(호버 시 웨이보 주황).

- 이미지 1장 / 동영상 1개 → 바로 다운로드
- 9칸 그리드 / 여러 이미지 → **첫 번째 항목만** 또는 **전체 N개 항목을 ZIP으로**

버튼은 **카드 아바타와 세로 중앙 정렬**되어 "이 게시물의 다운로드 버튼"임을 나타냅니다. 아바타가 화면을 벗어나면 버튼도 숨고, **카드가 고정 내비게이션 아래로 들어가도 함께 숨습니다**(내비게이션 위에 뜨지 않음). 가로로는 뷰포트 안에 유지되어 오른쪽 사이드바로 넘어가지 않습니다. 버튼이 없는 게시물이 있으면 콘솔에서 `__wbDl.debug()` 를 실행하세요([디버깅](#디버깅) 참조).

### 진행 링

동영상은 클릭 후 저장 창이 뜨기까지 보통 5~15초 걸립니다. 예전에는 반투명 상태만 있어 진행 여부를 알 수 없었습니다. 지금은 **버튼 바깥 고리가 곧 진행 표시줄** 입니다(두 사이트 동일).

```
클릭 ──▶ 미디어 해석(0→12%, 시간 기반 상승)
     ──▶ 바이트 수신(수신 바이트 / Content-Length 비율로 시계 방향 초록 채움)
     ──▶ 100% 채움  ← 이때 저장 창이 열림
     ──▶ "저장" 클릭  ← 버튼 원상 복귀, 채움 제거
```

- 받은 부분은 **초록**, 남은 부분은 **비어 있음**, 시계 방향으로 진행
- `Content-Length` 가 없으면 시간 기반으로 상승해 최대 92%에서 멈춥니다(완료한 척하지 않음)
- 저장 창이 열려 있는 동안 링은 100%를 유지하고, 다운로드가 `complete` 된 뒤에야 원상 복귀합니다
- 취소해도 버튼은 원상 복귀하며 오류도, 두 번째 저장 창도 없습니다

### 취소

**로딩 중 버튼을 다시 클릭하면 취소**됩니다. 이때 버튼은 채워진 사각형이 되고 호버 시 빨갛게 변하며 툴팁이 "다운로드 중, 클릭하여 취소"로 바뀝니다. "다시 누른다"는 동작이 납득되도록 만든 장치입니다.

취소는 UI만 접는 것이 아니라 세 계층이 모두 멈춥니다.

| 단계 | 취소 동작 |
| --- | --- |
| 미디어 해석(API 대기) | 로컬에 기록하고, API가 돌아와도 아무것도 보내지 않음(메뉴도 요청도 없음) |
| 바이트 수신 / ZIP 생성(그 5~15초) | `AbortController` 로 `fetch` 를 끊고 읽기 루프도 종료. 수십 MB를 헛되게 받지 않음 |
| 저장 창이 이미 열림 | `chrome.downloads.cancel()` 로 해당 다운로드 종료 |

취소는 조용합니다. 빨갛게 깜빡이지 않고, 재시도하지 않고, 두 번째 저장 창도 띄우지 않으며, 하단에 중립적인 토스트 "다운로드를 취소했습니다"만 표시합니다. 또한 **해당 다운로드를 시작한 버튼만** 취소할 수 있습니다. 다른 카드의 버튼을 누르면 "다른 항목을 다운로드 중입니다"라는 안내만 나오므로 남의 작업을 취소했다고 오해할 일이 없습니다.

### 저장 위치 설정

툴바 아이콘 → **설정 열기**. 설정 페이지는 사이트별로 두 개의 카드로 나뉩니다(**Instagram 다운로드 설정** / **웨이보 다운로드 설정**). 사이트 제목은 카드 테두리 바깥에 있고, 괄호 안의 사이트 이름은 클릭하면 해당 사이트로 이동합니다. 각 카드 내부는 이미지 그룹과 동영상 그룹으로 나뉘며 네 그룹은 서로 독립입니다.

| 항목 | 값 | 기본값 |
| --- | --- | --- |
| Instagram 이미지 폴더 / 해상도 | 사용자 폴더, 240P~4K | `Downloads\ins-download\images` |
| Instagram 동영상 폴더 / 화질 | 사용자 폴더, 240P~4K | `Downloads\ins-download\videos` |
| 웨이보 이미지 폴더 | 사용자 / 기본 | `Downloads\weibo-download\images` |
| 웨이보 이미지 화질 | 360P / 690P / 1080P / 원본 | 크기별 경로, 원본은 무압축 |
| 웨이보 동영상 폴더 | 사용자 / 기본 | `Downloads\weibo-download\videos` |
| 웨이보 동영상 화질 | HD / SD | 웨이보 API는 보통 이 두 단계만 제공 |

**사용자 폴더**: "폴더 선택"을 누르면 시스템 창에서 원하는 디렉터리를 고를 수 있습니다. 이후 모든 다운로드는 확인 창 없이 기록됩니다. 폴더 핸들은 IndexedDB에 저장됩니다.

> ⚠️ **브라우저를 재시작하면 권한이 만료됩니다**(File System Access API의 구조적 제한). 설정 페이지에 "재인증 필요"가 표시되면 **재인증** 을 눌러 같은 폴더를 다시 선택하세요. 이미 받은 파일에는 영향이 없습니다.

### 저하 동작

사용자 폴더를 지정하지 않으면 확장은 `chrome.downloads` 를 사용해 브라우저 기본 다운로드 폴더의 하위 폴더에 저장합니다. 브라우저 설정에 따라 이 경로에서도 저장 창이 한 번 뜰 수 있는데, 이는 브라우저 동작이며 확장이 우회할 수 없습니다.

## 동작 원리

### 전체 구조

```
Instagram 페이지                  웨이보 페이지
content.js(격리 월드)             weibo.js(격리 월드)
   │  chrome.runtime.sendMessage     │
   ▼                                 ▼
background service worker  ←──────  ┘   (msg.site 로 분기)
   │  ensureOffscreen()
   ▼
오프스크린 문서: 실제 바이트 수신(중단 가능) → blob / dataUrl / 디스크 쓰기
   │
   ▼
chrome.downloads.download()  →  지정한 폴더에 저장
```

- 콘텐츠 스크립트는 네트워크 본문을 만지지 않습니다. 페이지를 읽고 UI만 그립니다
- 무거운 작업은 오프스크린 문서가 담당합니다. DOM이 있고 호스트 권한이 있어 CORS 제약을 받지 않습니다
- service worker는 장기 상태를 두지 않습니다. 모든 것이 `progressId` 키의 맵이며 30초 후 정리됩니다

### 미디어 URL 해석: 5단계 폴백(Instagram)

1. `/api/v1/media/{media_id}/info/` (`X-IG-App-ID` 포함) — 가장 안정적, 캐러셀 전체와 모든 화질 반환
2. `/p/{shortcode}/?__a=1&__d=dis`
3. `/p/{shortcode}/embed/captioned/` HTML 정규식 추출
4. `/p/{shortcode}/` HTML 정규식 추출
5. DOM 폴백: `srcset` / `video.src` 를 가시성과 동영상 레이어 겹침으로 필터링

### 웨이보 미디어 해석

`/ajax/statuses/show?id=…` → 동영상 컴포넌트 API(`Component_Play_Playinfo`) → DOM 폴백. 이미지 URL은 화질별로 경로를 바꾸고, 없는 화질은 원본으로 폴백합니다.

### 왜 URL을 다운로더에 넘기지 않고 바이트를 먼저 받는가

다운로더가 직접 URL을 가져오면 요청 출처가 `chrome-extension://` 이고 페이지 Referer도 없습니다. 웨이보 CDN은 이 경우 **200 HTML 오류 페이지**를 돌려주고, Chrome은 그것을 `.htm` 으로 저장합니다. 이것이 "받은 파일이 `.htm`" 이라는 오래된 버그의 원인이었습니다. 먼저 바이트를 받아 파일명과 MIME 타입을 확장이 결정하면 이런 가능성 자체가 사라집니다. 오프스크린 문서가 만든 `blob:` URL을 거부하는 일부 Chrome 버전에서는 자동으로 `dataUrl` 로 재시도합니다.

Instagram에서는 같은 방식이 진행 링에 필요한 바이트 스트림도 제공합니다. 바이트 수신이 실패하면 **기존 직접 다운로드로 자동 폴백** 하므로, CDN의 일시적 거부 때문에 "원래 받을 수 있던 것"이 막히지 않습니다.

### 진행 링과 취소의 데이터 경로

```
content.js / weibo.js 가 progressId 생성
   │
   ├─▶ background 가 sender.tab.id 를 progressTabs 에 기록
   │
   ├─▶ offscreen save-media: getReader() 로 스트림 읽기, 120ms 마다 {loaded,total} 보고
   │        └─▶ background ─▶ tabs.sendMessage(type:"wb-dl-progress") ─▶ 링 그리기
   │
   ├─▶ chrome.downloads 호출 직전에 phase:"save"(=100%) 전송 → 이때 저장 창이 열림
   │
   └─▶ 다시 클릭 ─▶ action:"cancel" ─▶ offscreen abort(AbortController)
                                     └▶ chrome.downloads.cancel(downloadId)
```

하나의 `progressId` 가 전 과정을 관통합니다. 취소가 다운로드 요청보다 **먼저** 도착해도 기록되며(두 번 누르는 상황), 작업 시작 시 확인해 이미 취소되었으면 즉시 반환합니다. 세 단계의 취소 결과는 모두 `canceled` 로 정규화되어 상위에서는 "성공 / 취소 / 실패" 세 가지만 다룹니다.

> 두 사이트는 같은 진행 채널을 공유합니다(메시지 타입은 역사적인 `wb-dl-progress` 유지). 각 콘텐츠 스크립트는 자기 버튼의 링만 그립니다. `progressId` 접두사는 다르고(`ig…` / `wb…`), 기존 `wb-cancel` 과 새 `cancel` 액션을 모두 받습니다.

### 버튼을 `body` 에 두는 이유

초기 구현은 버튼을 `article` 안에 넣고 미디어 오른쪽 위에 배치했습니다. 두 가지 문제가 있었습니다.

1. **동영상의 투명 상호작용 레이어가 클릭을 삼킴** — Instagram은 동영상 위에 전체 화면 `<div>` 를 덮어 재생을 제어하므로, `z-index` 를 올려도 그 스태킹 컨텍스트 안에서는 소용이 없습니다
2. 기본 `···` 메뉴 버튼과 겹침

최종 방식은 버튼을 `document.body` 의 자식으로 두고 `position: fixed` + `z-index: 2147483647`, `getBoundingClientRect()` 로 카드를 따라가며 `scroll` / `resize` / 변경 감지 시 `requestAnimationFrame` 으로 일괄 재배치하는 것입니다. 버튼이 카드 **바깥**에 있으므로 카드 내부의 어떤 상호작용 요소와도 충돌하지 않습니다.

### 두 사이트가 서로 영향을 주지 않는 방법

| 분리 축 | Instagram | 웨이보 |
| --- | --- | --- |
| 콘텐츠 스크립트 | `content.js` | `weibo.js` |
| 스타일 접두사 | `.ins-dl-*` | `.wb-dl-*` |
| 스위치 키 | `enabled` | `weiboEnabled` |
| 폴더 키 | `imageDir` / `videoDir` / … | `weiboImageDir` / `weiboVideoDir` / … |
| 파일명 접두사 | `ins_image_` / `ins_video_` | `weibo_image_` / `weibo_video_` |
| 기본 폴더 | `ins-download/` | `weibo-download/` |

`background.js` 에서 둘이 만나는 지점은 각 핸들러 맨 위의 `if (msg.site === "weibo")` 한 줄뿐입니다.

## 알려진 제한

잘 되지 않는 부분을 솔직하게 적습니다.

1. **Instagram은 피드 `article` 만 지원**합니다. 게시물 상세 `/p/xxx/`, 단독 릴스 페이지, 스토리, DM, 프로필 9칸 그리드에는 **아직 버튼이 없습니다**.
2. **Instagram은 바이트 수신 실패 시 직접 다운로드로 돌아갑니다**(진행 링 없음, 취소도 불가). CDN의 일시적 거부로 "원래 되던 다운로드"를 깨지 않기 위한 의도된 설계입니다. 로그에 `ins 取字节失败，退回直拉` 가 남습니다.
3. **동영상이 포함된 캐러셀의 ZIP은 이미지 폴더로 저장됩니다**(Instagram만). `handleZip` 이 `imageDir` 만 읽기 때문이며, 웨이보는 콘텐츠 종류별로 분기합니다.
4. **매우 큰 ZIP은 메모리 위험**이 있습니다. 기본 폴더 방식에서는 ZIP을 dataUrl 문자열로 컨텍스트 간 전달하므로 약 100MB를 넘으면 실패하기 쉽습니다.
5. **동영상 화질 선택이 부정확**(Instagram만). `video_versions[].width` 가 0인 경우가 많아 실제로는 배열 마지막 항목을 사용합니다.
6. **Instagram 애니메이션 게시물 / 스토리 미디어**는 지원하지 않습니다.
7. **웨이보 선택자는 공개적으로 유지되는 유사 스크립트**(owendswang / firo1603의 다운로더)를 참고했고 API 필드는 `pic_infos` / `playback_list` / `Component_Play_Playinfo` 의 실제 구조에 맞췄지만, 로그인 상태에서 모든 페이지를 전수 검증하지는 않았습니다. 버튼이 없으면 먼저 `__wbDl.debug()` 를 실행하세요. 대개 `SEL` 수정만으로 해결됩니다.
8. **웨이보는 피드와 목록 페이지만** 지원합니다. 이미지 뷰어 오버레이, 단독 동영상 페이지, 헤드라인 기사, DM은 연결되지 않았습니다.
9. **웨이보 리포스트**는 리포스트된 게시물의 미디어를 가져옵니다(일부 레이아웃에서는 리포스트한 사람의 이미지도 함께 포함됩니다).
10. **저장 창이 뜨는 순간의 취소**는 Chrome의 `downloads.cancel` 처리에 의존하며, 일부 버전에서는 다운로드 목록에 "취소됨" 항목이 남을 수 있습니다(파일은 기록되지 않음).
11. 사이트 개편으로 해석 체인이 깨질 수 있습니다. Instagram은 `content.js`, 웨이보는 `weibo.js` 를 수정하세요.

- 이 확장은 **이미 브라우저에 렌더링된 공개 콘텐츠만** 읽습니다. 로그인 우회, 유료 콘텐츠 크랙, 대량 요청 수집은 하지 않습니다.

- 이 프로젝트는 Instagram / Meta, 웨이보 / 시나 웨이보와 아무런 관련이 없으며 승인받지 않았습니다.

빌드 단계가 없습니다. 수정 후 `chrome://extensions` 의 확장 카드에서 **새로고침** 아이콘을 누르고 해당 사이트 페이지를 새로고침하세요.

- `test-background.js` 는 `site` 없는 다운로드(Instagram 경로)와 `site: "weibo"` 를 각각 시뮬레이션해 폴더·접두사·`saveAs` 가 섞이지 않음을 검증합니다. background를 수정한 뒤 이걸 돌리면 Instagram에 영향이 없음을 확인할 수 있습니다

- `test-offscreen.js` 는 "HTML 오류 페이지가 .htm으로 저장되는" 옛 버그를 지킵니다. 다운로더가 네트워크 URL이 아니라 `blob:` / `data:` 를 받는지, 중단 후 다음 후보를 시도하지 않는지 검증합니다
- `test-weibo.js` 의 DOM 스텁은 탐지와 파싱에 필요한 부분만 구현해 최소 환경에서 실제 코드를 돌립니다

## 변경 이력

### v2.1.0

웨이보의 "진행이 보이고 언제든 멈출 수 있는" 경험을 Instagram에 적용하고 README를 4개 언어로:

- **Instagram에도 진행 링**: 해석 중 0→12% 시간 기반, 수신 중 `받은 바이트 / Content-Length` 비율로 시계 방향 채움, 바이트 수신 완료 시 100%(이때 저장 창이 열림), 창이 닫힌 뒤 원상 복귀. 데이터는 기존처럼 오프스크린 스트림 보고를 `progressId` 로 받습니다
- **Instagram도 취소 가능**: 로딩 중 다시 클릭하면 세 계층 모두 정지(로컬 링 해제, `AbortController` 차단, 창이 열려 있으면 `chrome.downloads.cancel()`). 버튼은 채워진 사각형이 되고 호버 시 빨강, 툴팁은 "다운로드 중, 클릭하여 취소"
- **Instagram 바이트 우선 방식으로 변경**: URL을 곧바로 `chrome.downloads` 에 넘기지 않고 오프스크린 문서가 실제 바이트를 받아 전달(확장자는 실제 파일 헤더로 결정). 수신 실패 시 **기존 직접 다운로드로 자동 폴백** 하여 CDN의 일시적 거부가 정상 다운로드를 망가뜨리지 않도록 했습니다
- ZIP 묶음도 진행과 취소 지원(항목 수 기준 진행, 취소 시 아카이브 폐기)
- `__insDl.*` 콘솔 진단 추가(`debug` / `media` / `ring` / `cancel` / `clearCache`). `__wbDl.*` 와 정렬
- 회귀 테스트 202 → **242개**(`test/test-content.js` 30개 추가, `test-background.js` 81 → 91개)
- README에 English / 日本語 / 한국어 추가 및 상단 언어 전환

### v1.3.1

로딩 중 "빠져나갈 길"을 추가. Instagram은 변경 없음:

- **로딩 중 다시 클릭하면 취소** — 이전에는 로딩 중 버튼이 죽어 있어 동영상 5~15초에서 나갈 방법이 없었습니다
- **취소는 세 계층에서 실행**: 해석 중단, 오프스크린 `fetch` 와 읽기 루프를 `AbortController` 로 차단, 저장 창이 열려 있으면 `chrome.downloads.cancel()`
- **로딩 중 버튼이 정지 아이콘으로**: 화살표에서 채워진 사각형으로, 호버 시 빨강, 툴팁 "다운로드 중, 클릭하여 취소"
- **조용한 취소**: 빨갛게 깜빡이지 않고, 재시도하지 않고, 두 번째 창도 없고, 중립 토스트만 표시
- **연속 클릭 방지**: 하나의 `progressId` 가 세 단계를 관통하고, 다운로드 요청보다 먼저 도착한 취소도 기록해 작업 시작 시 확인
- 해당 다운로드를 시작한 버튼만 취소 가능
- 콘솔에서 `__wbDl.cancel()` 로 수동 취소 가능
